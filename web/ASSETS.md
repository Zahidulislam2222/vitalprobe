# Asset provenance

- `public/media/signal-instrument.webp`: generated for VitalProbe with the built-in
  OpenAI image-generation tool. FFmpeg encoded the web version; the source remains
  in private project recovery storage.
- Decorative hero prompt: “Premium Blender-style studio render of a transparent mint
  glass torus with branching mint filaments and amber signal lights, a suspended inner
  glass sphere, brushed graphite plinth and dark charcoal background. Wide composition,
  sculpture on the right, negative space on the left. No text, logos, people or anatomy.”
- `public/media/signal-instrument.mp4`: generated with Seedance 2.5 through OpenRouter,
  one explicitly authorized six-second 720p request. FFmpeg converted the output to H.264,
  yuv420p, no audio and a fast-start MP4. Authoring prompt: the same mint glass sculpture,
  fixed camera, gentle signal lights and subtle suspended-sphere movement; no text or people.
  The full request, original output, receipt and actual charge are retained privately.
- `public/favicon.svg` and the wordmark pulse: original code-native project artwork.
- Icons: Lucide React (ISC); no third-party brand endorsement is implied.
- Manrope and Space Grotesk: self-hosted variable fonts, SIL Open Font License.
- The saved run and report are fictional evidence from the project's intentionally weak
  scripted target. Hero art is unrelated to the reported test outcomes.

Generated assets are used as visual decoration only. Clinical content remains draft;
images, video and automated tests do not replace qualified human review.

The hero video is muted, looping, inline and automatic when permitted. A static poster
remains available when autoplay is blocked or the system requests reduced motion.
Motion controls are intentionally absent. Keep source generation credentials and
receipts out of the public bundle; this file records provenance, not provider access.

Before replacing an asset, review its license/provenance, encoded dimensions, transfer
size, poster fallback and accessibility behavior. See the [frontend guide](README.md)
and [delivery plan](../docs/scalability.md) for build and asset-budget requirements.
